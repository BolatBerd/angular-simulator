  2 задание
    Для стратегии по умолчанию интерфейс обновится автоматически,
    ngDoCheck сработает один раз, после каждого асинхронного события.
    ChangeDetectorRef не нужен — Angular сам запустит проверку.
    В сценарии 1, клик триггерит change detection один раз.
    Во втором – setTimeout, тоже 2 раз.
    После Promise – 1 раз по завершению then.
    После HttpClient-запроса – 3 раза.
    С setInterval – сразу после нажатия и при каждом срабатывании интервала будет запускаться проверка.
    А в комбинированном сценарии проверки будут запускаться последовательно — обычно сначала после клика,
    Promise, и потом setTimeout 2 раза. В этих случаях ChangeDetectorRef не требуется,
    если использовать ChangeDetectionStrategy.Default.

  3 задание
    Часть 1 markForCheck()
      Ответы
        1. Что произошло после вызова markForCheck()?
          Компонент был помечен флагом «требует проверки» (dirty).
        2. Обновился ли интерфейс сразу?
          Нет. 
        3. Когда фактически произошёл Change Detection?
          На следующем глобальном тике.
        4. Почему без markForCheck() интерфейс не обновлялся?
          При OnPush Angular проверяет компонент только при следующем проходе.
    Часть 2 detectChanges()
      Ответы
        1. Чем поведение отличается от предыдущего сценария?
          detectChanges() не ждёт следующего глобального тика — он запускает проверку немедленно
        2. Выполняется ли Change Detection немедленно?
          Да. 
        3. Какие компоненты были проверены?
          Сам компонент ChangeDetectionOnPushComponent и его родители.
          Родители и соседние компоненты не проверяются.
        4. В каких случаях использование detectChanges() предпочтительнее?
          Нужно обновить view немедленно, до следующей строки кода (например, перед ручным измерением DOM).
          Код выполняется вне Zone.js и глобальный тик не ожидается.
          Нужно обновить только этот компонент, не запуская проверку всего приложения.
          Отладка конкретного участка дерева.
    Часть 3. detach()
      Ответы
        1. Обновляется ли интерфейс?
          Нет, ни в одном из случаев.
        2. Выполняется ли ngDoCheck()?
          Нет. Отсоединённый компонент полностью исключается из дерева проверок
        3. Почему Angular перестал проверять компонент?
          detach() отсоединяет view компонента от дерева change detection.
        4. Какие способы изменения значения больше не работают?
          Все четыре:
            (click) — метод выполняется, UI не обновляется;
            setTimeout() — таймер срабатывает, тик Zone.js есть, но view вне дерева;
            setInterval() — то же самое;
            Promise — микротаск выполняется, UI молчит.
          Вывод: detach() «глушит» обновление независимо от источника изменений — это полное отключение от CD.
    Часть 4. reattach()
      Ответы
        1. Что изменилось после reattach()?
          Компонент снова подключён к дереву CD. Изменения count опять попадают в интерфейс:
          клик, setTimeout, setInterval, Promise — всё снова обновляет DOM
        2. Когда компонент снова начал участвовать в Change Detection?
          Сразу после вызова reattach() — view возвращается в дерево, и первый же последующий цикл CD 
        3. Нужно ли дополнительно вызывать detectChanges() или markForCheck()?
          Нет при Default.
          При OnPush, Да, рекомендуется.
